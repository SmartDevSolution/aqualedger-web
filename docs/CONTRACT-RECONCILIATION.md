# M1 contract reconciliation

This note replaces the earlier foundation statement that no backend contract artifact was available. The web repository consumes the unmodified OpenAPI artifact from backend commit `1f3df95c0e1684cdc846cbe268d92f3222d09cc9` (contract version `0.1.0`, OpenAPI `3.1.0`). Its Git blob SHA is `839d9e04857f8acec5c6adc6503596bf0fba3789`, and its SHA-256 is `8081f099ab74b4724c93828cb4ba841ffddf235de56f090341f7ffe10a101040`. The binding product contract is central revision 8 at `413dc884a22b05e9f8ed239eb8236e230c640937`, `docs/current/11-M1-CONTRACT-FREEZE.md`.

The latest merged central baseline is `db404bffe536fc969eb0069deba1acaf3d4b1707` (PR #4). Central PR #5 and web PR #3 are open governance proposals and are not treated as merged policy. Routine implementation below follows the ratified contract; unresolved contract/access mismatches are disclosed rather than resolved in this repository.

## Compatible surface consumed

The artifact contains exactly the M1 routes `POST /analyses`, `GET /analyses/{analysis_id}`, `GET /analyses/{analysis_id}/result`, and `GET /sources`. The web client generates its types from that file. It sends an idempotency key for each explicit submit attempt, treats `IDEMPOTENCY_CONFLICT` as an explicit error, and sends only the AOI, ISO start/end dates, and presentation locale. Locale and browser timezone never trigger a submission. The UI has no history, zones, time-series/trend, or priority presentation; those fields are absent from the consumed result schema.

## Differences requiring backend/central follow-up

1. **Failed-run evidence status:** freeze B4 requires `evidence_status` to be absent when `execution_status` is `FAILED`. The generated status and result schemas require it. Backend `AnalysisStatusResponse` also declares it required and the status route constructs it unconditionally. The web refines the generated status type using the frozen failure rule and accepts a failed status only when the JSON field is absent; a contradictory response is reported as contract-invalid. The web cannot make the backend response conform to the freeze.
2. **Authorization declaration and delivery:** the artifact marks `Authorization` optional on analysis create/status/result. Backend `PrincipalDep` requires a bearer token and returns `UNAUTHENTICATED` without one. No browser-safe token issuance or approved session provider is present in the web product. The client sends no secret or invented token. Live analysis submission/reopen is therefore BLOCKED pending the approved access model; source status is independently callable by the backend route.
3. **Frozen error envelope and responses:** the artifact does not describe `{error: {code, params, request_id}}` or the frozen 400/401/403/404/409/503 response shapes. It documents only 202/200 and framework validation responses. The client recognizes the frozen envelope at runtime and maps known machine codes; framework prose is never parsed. Backend errors map `NOT_READY` to HTTP 200, but the OpenAPI result response describes only an `AnalysisResult`, so this error response is not represented in the generated contract.
4. **Baseline result field:** freeze B4 requires a baseline identity in the result. The generated `AnalysisResult` schema has pipeline and method versions plus provenance, but no explicit `baseline` field. The UI displays the fields that exist and does not synthesize a baseline object.
5. **Acquisition tie-break metric:** freeze B2 rule 5 defines a mosaic cloud metric as the maximum `eo:cloud_cover` across selected tiles of a date. The pinned backend pipeline computes `_mean_cloud_cover` and uses that mean when ranking candidate dates. The web client does not calculate or replace the winner; this backend method divergence is reported for correction/review.
6. **No-eligible-date reason:** freeze B2 rule 6 requires `NO_ELIGIBLE_ACQUISITION`. The pinned pipeline instead returns limitations `NO_SCENES_FOUND` when search returns no items and `NO_DATE_MEETS_MIN_VALID_COVERAGE` when all evaluated dates are rejected. The web localizes the returned reason codes and exposes this code difference rather than changing the API response.
7. **Georeferenced map preview:** freeze B9 requires a backend-rendered, georeferenced preview with recorded bounds/CRS and a fixed colormap. The generated artifact item is an arbitrary object. At the pinned backend SHA, the worker writes a float GeoTIFF and manifest, records `bounds=None`, and returns only `kind`, `storage_key`, and `size_bytes`; the result route may add a short-lived `preview_url` when Storage is configured. This is not a browser-renderable image/bounds contract. The result panel can show actual coverage/statistics/provenance, but the map overlay is marked NOT RUN and no raster is fabricated or decoded in the browser.

The web PR must link these exact differences for the backend owner and report the corresponding UI paths as NOT RUN/BLOCKED. Any correction to the generated contract or ratified freeze belongs in the owning repository and requires its review; the checked-in artifact is not edited here.
